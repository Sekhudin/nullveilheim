# Home Manager

> Scope: configuring user-level options, activation, themes, and SOPS key paths.

[`Home Manager`](https://nix-community.github.io/home-manager/) modules provide user-level configuration for shells, terminals,
themes, packages, session variables, activation, and user programs.

The main user configuration is shared by the integrated and standalone
profiles. User-specific selections are made through `homeCore` and
`homeDesktop` options.

## Core Options

The options are defined in `modules/home/core/options.nix` using the
[Nixpkgs module and library helpers](https://nixos.org/manual/nixpkgs/stable/#sec-functions-library).

## Option Summary

| Option | Supported values | Default |
| --- | --- | --- |
| `homeCore.shell` | `fish`, `zsh` | `fish` |
| `homeCore.terminal` | `ghostty`, `alacritty` | `ghostty` |
| `homeCore.theme` | `aurora`, `obsidian`, `nocturne` | `aurora` |
| `homeCore.activation.enable` | `true`, `false` | `true` |

### Shell

Choose Fish:

```nix
homeCore.shell = "fish";
```

Or choose Zsh:

```nix
homeCore.shell = "zsh";
```

Supported values are `fish` and `zsh`. The default is `fish`.

### Terminal

Choose Ghostty:

```nix
homeCore.terminal = "ghostty";
```

Or choose Alacritty:

```nix
homeCore.terminal = "alacritty";
```

Supported values are `ghostty` and `alacritty`. The default is `ghostty`.

### Theme

Themes are selected with:

```nix
homeCore.theme = "aurora";
```

The available themes are:

- `aurora`
- `obsidian`
- `nocturne`

These names are defined in `shared/colors.nix`. The selected theme provides
colors, semantic tokens, opacity, and application-specific values used by the
desktop and terminal modules.

## Activation

Activation is enabled by default:

```nix
homeCore.activation.enable = true;
```

When enabled, the activation modules can:

- Install and import SSH keys.
- Import GPG keys.
- Generate Git identities.
- Create profile-specific SSH aliases.
- Clean up broken Linux systemd user-unit links.
- Configure [SOPS-Nix](https://github.com/Mic92/sops-nix) secrets and Git
  `sopsdiffer` integration.

To use the Home Manager configuration without secret-dependent activation:

```nix
homeCore.activation.enable = false;
```

When disabled, the activation scripts, SOPS configuration, `sops` and
`gnupg` packages, secret declarations, and Git SOPS diff integration are not
enabled. The [SOPS-Nix Home Manager module](https://github.com/Mic92/sops-nix#home-manager-module)
remains imported so its options remain available, but this repository's SOPS
configuration is guarded by the option.

Profiles for GPG keys, SSH keys, and Git identities are configured separately:

```nix
homeCore.activation = {
  enable = true;
  gpgKeys = [ "personal" ];
  sshKeys = [ "personal" ];
  gitIdentities = [ "personal" ];
};
```

Do not commit plaintext secrets. The encrypted SOPS file is located at
`secrets/secrets.yaml`.

### SOPS Key Structure

The repository documents the expected key paths, but never documents secret
values. The key declarations are generated by the helper in
[`shared/lib/sops.nix`](../shared/lib/sops.nix) and consumed by
[sops-nix](https://github.com/Mic92/sops-nix).

The expected structure is:

```text
secrets.yaml
├── gpg_keys
│   └── <profile>
│       ├── email
│       ├── private_key
│       └── owner_trust
├── ssh_keys
│   └── <profile>
│       ├── path
│       └── private_key
├── git_identities
│   └── <profile>
│       ├── name
│       ├── email
│       ├── signing_key
│       ├── ssh_key
│       └── gitdirs
│           ├── w1
│           ├── w2
│           └── w3
└── tokens
    └── personal
        └── nullveilheim_mcp
```

`<profile>` is a configured profile name such as `personal`. The helper
converts dotted Nix paths into nested SOPS key paths. For example:

```text
gpg_keys.personal.email
→ gpg_keys/personal/email
```

The corresponding profile option is configured under
`homeCore.activation.gpgKeys`, `homeCore.activation.sshKeys`, or
`homeCore.activation.gitIdentities`. This section describes key names only;
do not decrypt or copy any secret values into documentation.

## Example Profile

```nix
homeCore = {
  standalone = true;
  shell = "zsh";
  terminal = "alacritty";
  theme = "aurora";
  activation = {
    enable = false;
  };
};

homeDesktop.enable = false;
```

The `standalone` option identifies how the profile is integrated; it does not
by itself disable desktop or activation modules.

## Integrated and Standalone Profiles

The integrated `syaikhu` profile is attached to NixOS and nix-darwin hosts by
`parts/ez-config.nix`. Its generated outputs are named after the host, such as
`homeConfigurations.syaikhu@t14`.

The `syaikhu-sa` profile is registered as a standalone Home Manager
configuration and can be applied directly:

```sh
home-manager switch --flake .#syaikhu-sa
```
